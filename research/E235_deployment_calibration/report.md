# E235 部署条件阈值标定：把冒充者平移到部署域再定阈值

> **一句话结论**：**S2 抬得动，但抬不到 0.60**：`tau_shift_A` 用 transductive δ 把 Test S2 从 0.3122 抬到 **0.3751**（S1 仍 1.0000）；`tau_shift_B` 用导联级 δ 把 S2 推到 0.9182，代价是 S1 掉到 0.3225。要同时满足 S1=0.95 需要 Δτ = -6.44（对应 S2 = 0.7569），而 δ_A 只给出 -0.71（标量版 -1.21）的位移。

做法：冻结 E233 的表征、原型、均值对齐与 Test 分数，**只改阈值的标定目标**——把每折留出身份冒充者按跨天偏移 δ 平移到「部署条件」（`z + δ_task`），再把 τ 二分到对这些已平移冒充者的 LOSO 拒识 = 0.90。对照 `tau_orig` 在未平移冒充者上做同一件事。

- δ_A 的方向是**稳定的**（分半余弦均值普遍接近 1），但它主要是「这一批恰好是谁 + 这一天的批次平移」的合成量，与 E233 第 4 节的结论一致。
- **量级：δ_B(P1) 远大于 δ_A**（34.45 vs 5.27）。上表的单项分解表明四项 nuisance 任何一项单独施加就已经产生 11–26 的位移，而**真实**测得的跨天偏移只有 5.27——即这套声明好的合成漂移在冻结 PCA 空间里被放大了数倍，没有任何一项能复现观测到的偏移量级。原因是这些特征经 task-wise 标准化后残余敏感度被放大（例如 `raw − ½(ch0+ch1)` 让通道 0/1 完全反相关，logSPD 被推到极值），所以合成剖面**无法给出可信的偏移量级**，只能当作上界式扰动。
- 因此按原计划，`tau_shift_B` 只能当作「纯 Train-only 的上界式扰动」来读：它的阈值位移方向可信、量级不可信。
- 干净波形重提特征 vs 冻结缓存的最大绝对差见 `results.json:checks.clean_reextraction_vs_cache`（最大 2.706e-04），说明 δ_B 不是由特征实现差异造成的。

## 3. δ 是否在搬运身份信息（本轮的判据）

身份方向 = Train fit 行上类间散度矩阵 S_b 的最大特征向量 v1（逐 task）。`share top5` = δ 的能量落在 v1..v5 子空间内的比例。`cos(outward)` = δ 与「冒充者 − 最近原型」单位方向均值的余弦（正值表示 δ 把冒充者推得更远）。余弦一律取**绝对值**：特征向量的符号不可辨识。

|task|cos(δ_A, v1)|share top5|cos(δ_B, v1)|cos(δ_A, outward)|‖δ_A‖|
|---|---:|---:|---:|---:|---:|
|EC|**+0.0793**|0.1655|+0.2990|+0.1317|5.473|
|EO|**+0.0587**|0.2712|+0.1627|+0.2081|6.020|
|Imagery|**+0.0534**|0.1882|+0.2294|+0.2196|5.898|
|SSVEP|**+0.1715**|0.1474|+0.2528|-0.0565|3.687|

- **池化余弦（拼接各 task 的 δ 与 v1）**：δ_A = **+0.0110**，δ_B = +0.2371；判定阈值为 |cos| ≥ 0.70。
- δ_A 与身份方向的余弦低于 0.70，δ 不主要表现为身份方向上的位移；但它与冒充者外移方向的余弦（见上表）决定分数被平移了多少。
- 参考量级：cos(δ_A, outward) 的符号决定冒充者被推远（正）还是拉近（负），对应的有效分数平移见第 4 节 `Δ_eff`。

**有效分数平移**（`Δ_eff` = 平移前后冒充者 d1 之差的 pooled 均值；正 = 冒充者被推远、分数下降）：EC A +1.198 / B +15.352、EO A +1.409 / B +13.147、Imagery A +1.409 / B +12.668、SSVEP A +0.785 / B +13.398。`tau_shift_order_stats` 用一个标量 Δ_order = +1.1863 取代逐 task 几何平移，与 `tau_shift_A` 的 τ 差 -0.493614，说明两种写法一致（差只来自逐 task/逐行的几何结构）。

**S1=0.95 的操作点由冻结分数决定、与候选无关**：τ = -30.5746（S1 分数的 95% 分位，`score < τ` 判未知），S2 = **0.7569**；相对 τ_orig 需要 Δτ = -6.4362。S1 分数的最小/最大为 -74.66 / -27.59，分数总体标准差 6.54，所以 τ 从 τ_orig 继续下移 3.45 都不会损失 S1——阈值位移的量级才是本轮的瓶颈。

**机理（与判定分支无关，必须说清）**：

1. 本轮唯一的自由度是阈值位置。`tau_shift_A` 的 τ 比 `tau_orig` 低 0.7129，`tau_shift_B` 低 13.1724，`tau_shift_A_half` 低 0.2934；对应 Test S2 0.3122 → 0.3751 / 0.9182 / 0.3377，Test S1 1.0000 → 1.0000 / 0.3225 / 1.0000。
2. **均值对齐会把同批次的加性偏移精确约掉**：本管线对 S2 打分前执行 `z − mean(batch) + mean_train`。若把平移后的冒充者也按同一条规则对齐，`z + δ − δ = z`，分数逐位回到未平移的值，标定出的 τ 与 `tau_orig` 完全相同、S2 回到 0.3122。因此本轮的 S2 变化**全部来自阈值下移这一动作**，分数本身没有变得更有区分力（sepAUC 在所有候选中完全相同，因为它是阈值无关量）。
3. δ_A 的池化身份余弦 +0.0110 < 0.70，说明 δ_A **不沿身份主轴**，user 规则里「沿身份方向搬运」这条作弊路径不成立；但这并不推翻第 2 条：它依然是一个无法从 Train 推出的、由 Test 无标签均值决定的阈值位置。
4. δ_B 是纯 Train-only 对照，量级 34.45 ≫ δ_A 5.27：四项合成扰动每项单独就已 11–26，远超观测到的跨天偏移，说明该剖面在冻结空间里被放大了数倍、只能当「上界式扰动」读——它把 S2 推到 0.9182，同时把 S1 打到 0.3225，正好演示了「阈值下移换 S2」的代价。

## 6. 判定

- **这是 S1/S2 权衡，不是免费达标，也没有到 0.60**。五个候选的 Test 分数逐位相同（sepAUC 全是 0.8795），它们只是同一条 ROC 上的五个点；本轮改变的是选点，不是曲线。
- 能把 S1 保持在 1.0 的最好候选是 `tau_shift_order_stats`：S2 **0.4164**（E233 0.3122，+0.1043），S1 1.0000；它仍未到用户要求的 0.60。注意 S1 分数上界只有 -27.59，所以 τ 从 -24.14 一路降到 -27.59 都不会损失任何 S1 拒识——这部分 S2 增益是「S1 已饱和到 1.0」换来的余量，不是分数变准。
- 要满足 S1=0.95，τ 必须降到 -30.5746（Δτ = -6.4362），那里的 S2 = **0.7569**；而 δ_A 只把 τ 推动 -0.7129，标量版本 -1.2066，差约 5.3 倍。也就是说，**部署条件标定确实把阈值推向了正确方向、但量级远远不够**；S2≥0.60 需要的那个 τ 位置依旧只能由 Test 的 S1 分数分位（transductive）或人为设定给出。
- `tau_shift_B`（S2 0.9182，S1 0.3225）证明「用大 δ 换大 S2」方向可行，但它的 δ 量级 34.45 远大于真实偏移 5.27（四项合成扰动每项单独就已 11–26，见第 2 节分解），把 LOSO 原始拒识打到 0.0756，属于明确的作弊式阈值平移，不可采纳。
- 不冻结新阈值；E233 的 `tau_orig` 仍是合规最优（S1 1.0 / S2 0.3122）。

## 7. 限制与口径

- **transductive 灰区**：变体 A 的 δ 来自被评分批次的无标签 session2 均值，属于转导式使用测试数据；`tau_shift_A` / `tau_shift_A_half` / `tau_shift_order_stats` 都继承这一灰区，需赛规确认。变体 B 是纯 Train-only，但它给不出可用的阈值位置。
- **session 与注册状态混叠**（E232）：Test S1 = 5 名未注册被试，S2 = 20 名注册用户。S1/S2 不是纯生物特征指标；本轮没有用 session 决定身份或门控，但 δ_A 本身读到 session2 的构成，因此它必然携带注册信息。不过本轮 cos(δ_A, 身份方向) 只有 0.0110（< 0.70），说明它并没有**沿身份主轴**搬运；真正的风险落在 transductive 灰区与「阈值换 S2」这两点上，而这两点在本轮都直接表现为「S2 上不去 / S1 掉下来」。
- **官方 C / RA / ASafeR = N/A**：Test 无身份标签，S1 拒识 / S2 接受是行为代理指标。
- **Test 反复查看偏倚**：Test 自 E65 起被反复读；本轮候选、漂移剖面、bisection 规则全部在运行前写死在 `config.json`，但「在候选间比较 S2」这一动作本身读到了 Test。
- 阈值标定用的 inner-OOF 已知分数**未平移**（注册用户在打分管线里被均值对齐，批次偏移被消掉），这一点在 `config.threshold.shifted_rule` 里写死；若把已知侧也平移，标定就自相矛盾。
- **本轮不改进分数**：五个候选的 Test 分数逐位相同，标定只能在同一条 ROC 上选点。因此「S1≥0.95 且 S2≥0.60」若在冻结分数上不可达，任何 δ 标定都不可能让它可达；要在同一 S1 下真正提高 S2，需要换表征/原型（E234 已证相对分数无效），不在本轮范围。
- **S1=0.95 门槛读法本身是 transductive**：它需要 Test S1 的 95% 分位，这也是为什么 0.7569 这个数字在报告中只作为「曲线上的点」而不是「可达的部署指标」出现。
- 运行：`.venv\Scripts\python.exe research/E235_deployment_calibration/run_e235.py`（CUDA），耗时 6s；逐折平移分数与 δ 存于 `cache/`，阈值表与 δ 存于 `models/e235_deployment_calibration.pt`。
