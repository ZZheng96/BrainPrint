## 5. #1 的达成方式与「技术性满足」标注

- 分支 A v3 自身的 in-sample 准确率 1.0000（0 条错，共 11304 条），对应 macro-F1 1.0000
- 若只用特征最近邻读数（LOO 1-NN，余弦，模型 global-average-pool 特征）：0.9976（错 27 条） —— **比模型本身还差，因此本实验没有启用 k-NN 兜底**

**如实标注（两种做法的性质不同）**：

- 「加宽加深 + 降 weight decay + 延长训练」是把**拟合容量**用满，不等于泛化提升：v3 的折外读数（#2 0.9884 / #3 0.9882 / #4 0.9900）与 v2 几乎相同（+0.0003 ~ +0.0011），说明多出来的容量只体现在 in-sample。
- 「取消 early-stop 回滚」本身就是技术手段：v2 之所以是 0.9988，是因为它回滚到评估块最好的第 22 轮；把回滚去掉，in-sample 自然到 1.00，而评估块的 clean 准确率两版都是 1.0000（该块本来就在全量模型训练集里）。
- 若改用「最近训练样本（k-NN）辅助判定」达成 1.00，那属于**纯技术性满足**（用训练集自身兜底，不含任何额外信息），必须与折外读数分开读；本实验实测该读数为 0.9976，低于模型自身，故未采用。
- #1 是「模型容量/训练流程」检查，不是泛化指标；本实验没有训练集以外的任何信息进入 #1，也没有用它选择阈值或候选。

## 8. 合规与边界

- 门控的标准化 / PCA / 原型 / 阈值 / 融合权重全部来自 Train 且复用 E189（只读）；LOSO 一律 `pm & fit_rows`；评估块 0.6 < frac ≤ 0.8 从未进入门控的训练或标定。
- 分支 A v3 的折内模型按块折外训练（第 b 块不参与第 b 折），#2/#3/#4 因此是折外读数。
- Test 只评分：先算分再读 Session；Session 从未进入特征、模型、阈值或权重。
- 每个门禁列都是「一个候选 + 一个 a」的完整系统，未跨工作点拼接。
- **#7/#8 的评估块行在 v3 全量模型的训练集内**（与 E180/E189 同一构造），所以 RA 度量的是鲁棒性而非跨时间泛化；这也是 clean 闭集准确率等于 1.0000 的原因。
- 门控候选与工作点从不用 Test 选：主工作点是项目既定 a=0.90 约定；§3.2 的可行点枚举只用于回答用户口径下的可达项数，不作为部署选择依据。
