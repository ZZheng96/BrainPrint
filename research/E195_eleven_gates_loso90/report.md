## 0. 结论

1. **#11 本身很容易满足**：E183 融合、E192 WCCN 距离比、E65+WCCN 融合的 `loso_strict` 都在 0.96 以上；E65 单门控只有 0.6448，subwin6 只有 0.3982。
2. **(a) 几何上存在，部署上不存在。** 在 349 个候选×权重点里，有 **3 个**同时满足 `loso_strict > 0.90` 与 Test 双 ≥0.70，全部是 `E183 + E65 + subwin6` 三路融合，Test min 0.7017–0.7221、strict 0.9278–0.9640，是一道很窄的缝。但它们只能靠 Test 审计找到；按“权重只按 loso_strict 选”的合规规则，每个融合都会退化到 E183 单门控（strict 0.9848，Test min 0.2733）。
3. **(b) Pareto 前沿**从 E183（strict 0.9848 / Test min 0.2733）经三路融合过渡到 subwin6（strict 0.3982 / Test min 0.6916）。strict ≥0.90 的最高 Test min 是 0.7221（e183_fuse 0.30 + e65_dist 0.20 + subwin6_dist 0.50，strict 0.9278）。最好的可计数折中是 `E183 0.4 + E65 0.3 + subwin6 0.3`：strict 0.9640、Test S1 0.7052 / S2 0.7087、strict AUROC 0.9807。
4. **(c) 该折中单工作点通过 8/11 项**：#1–#5、#9–#11 通过；#6（U@95）、#7（RA）、#8（ASafeR）未通过。

## 1. 两套 LOSO 的定义与数值对照

- `loso_std`（E143 协议）：task-wise 均值/标准差用该 task 的全部 Train 行（含留出身份 h），PCA 基用全部 20 个身份的 fit_rows 拟合；只有原型用 `pm & fit_rows`（19 个已注册身份）。
- `loso_strict`：留出身份 h 的 fit 块也排除在 task-wise 标准化与 PCA 之外；均值/标准差、PCA 基、原型都只用其余 19 个身份（`keep` / `keep & fit_rows`）。
- 两者都是 20 折：known = 19 个身份的 0.6<frac≤0.8，unknown = h 的同一窗口；阈值取折内 known 的 `1-a` 分位；表中为 a=0.90 的拒识率与合并 AUROC。

## 3. 明确回答 (a)(b)(c)

### (a) 是否存在同时满足 LOSO>0.90 与 Test S1/S2 双 ≥0.70 的门控？

**分两层回答。**

- **作为一组固定权重，存在。** 349 个点里有 3 个：`E183 0.3 + E65 0.2 + subwin6 0.5`（strict 0.9278 / S1 0.7227 / S2 0.7221）、`E183 0.4 + E65 0.3 + subwin6 0.3`（strict 0.9640 / S1 0.7052 / S2 0.7087）、`E183 0.3 + E65 0.3 + subwin6 0.4`（strict 0.9360 / S1 0.7471 / S2 0.7017）。三者都是三路融合，双 0.70 的余量只有 0.0017–0.0221。
- **作为可部署门控，不存在。** 权重禁止用 Test 选；按 `loso_strict` 最大选权，每个融合都退化到 E183 单门控（strict 0.9848，Test S1 0.2733 / S2 0.8173，min 0.2733）。也就是说，上一条的“存在”依赖 Test 审计来定位权重，不满足本实验的合规约束。
- **只用有 5 块 OOF 的距离/WCCN 流（E189/E191 项目口径）时 feasible = 0**：3 个可行点都依赖 E183 的 paired LOSO 阈值。因此换阈值口径也不会把结论从“不可部署”变成“可部署”。

### (b) 若不存在，Pareto 前沿在哪，最好的折中是什么？

前沿见 §2.3：从 `e183_fuse`（strict 0.9848 / min 0.2733）沿 `e183+e65+wccn`、`e183+e65+subwin6` 过渡到 `subwin6`（strict 0.3982 / min 0.6916）。**前沿在 strict≈0.90 处的 Test min 约 0.70–0.72**，不是单调的“strict 越高 Test 越好”，而是一道窄缝。
两条边界各自能到：**Test min ≥0.70 时 strict 最高 0.9640**（0.4/0.3/0.3）；**strict >0.90 时 Test min 最高 0.7221**（0.3/0.2/0.5，但 strict AUROC 0.9716）。把 strict 完全放开，Test min 的最高点仍是 0.7221；再往 subwin6 偏，min 不再上升（S1 掉得比 S2 快）。

最好的可计数折中是 `E183 0.4 + E65 0.3 + subwin6 0.3`：strict 0.9640、strict AUROC 0.9807、Test S1 0.7052 / S2 0.7087。若按“Test min 最大”选，则是 e183_fuse 0.30 + e65_dist 0.20 + subwin6_dist 0.50（min 0.7221），但它的 strict AUROC 只有 0.9716，会丢掉 #5。

### (c) 最佳折中方案能通过 11 项中的几项？

**8/11**。未通过 #6（U@95 0.8831，目标 ≥0.95）、#7（RA 0.9473 @SNR30，目标 ≥0.95）与 #8（ASafeR 0.9617 @SNR30，目标 ≥0.98）；在 SNR20 下 #7/#8 分别只有 0.0807 / 0.2364。#5 以 0.9807 擦线通过，#9/#10/#11 分别以 0.7087 / 0.7052 / 0.9640 通过。

## 5. 为什么 #11 与 Test 双 0.70 难以兼得（定量）

1. **两个约束争的是不同的东西。** #11 只用同批同会话的 19 身份拟合；Test 双 0.70 要求门控在另一批采集的 5 个未注册者（S1）与 20 个注册者的 session2（S2）之间划出同一方向的边界。E194 已证明 S1 与 Train 的域可分性 AUC 0.9789，而 S2 只有 0.8698。
2. **单门控的 Test S1-vs-S2 排序能力决定上限。** E183 融合的 AUC(S2 vs S1)=0.593，WCCN 距离比 0.389，E65 距离 0.758。E183 的 strict 拒识 0.9848，但它在 S1/S2 上几乎不排序（S1 均值 0.324、S2 0.420，差距远小于 LOSO unknown 的 −0.985）。要把 Test min 抬到 0.70，门控必须接近 E65 的排序能力；而 E65 的 strict 只有 0.6448。
3. **前沿是凸的、缝很窄。** 在 349 个点里，strict>0.90 且 min≥0.70 只有 3 个，全部落在 `E183 0.3–0.4 + E65 0.2–0.3 + subwin6 0.3–0.5`。再往 E183 偏 0.1，min 掉到 0.69；再往距离流偏 0.1，strict 掉到 0.90 附近且 min 不再上升（S2 开始下降）。
4. **Train-only 选权一定退化。** strict 拒识在 E183 处最高（0.9848），任何距离流权重都是“用 strict 换 Test min”。合规规则不允许用 Test 选权重，所以部署系统只能停在 E183（min 0.2733）或纯 E65（strict 0.6448，min 0.5569/0.5960）两端；中间的可行点没有 Train-only 的选择依据。**差距**：Train-only 的 E183 单门控 Test min 0.2733，距双 0.70 差 0.4267；纯 E65 的 strict 0.6448，距 0.90 差 0.2552；0.4/0.3/0.3 才把两个差距压到 0.005/0.009，但它只能靠 Test 审计定位。
5. **#5/#6 也在这条缝上。** 0.3/0.2/0.5 点 min 更高（0.7221），但 strict AUROC 只有 0.9716，丢掉 #5；0.4/0.3/0.3 的 strict AUROC 0.9807，刚好过 0.98。#6（U@95）更硬：在全部 30 个 Test min≥0.70 的点里，U@95 最高就是 0.8831（即 0.4/0.3/0.3）；即使 E183 单门控也只有 0.909，WCCN 单门控 0.9581 但 Test S2 只有 0.188。**没有一个候选能同时把 #6 抬到 0.95 又保住 Test 双 0.70。**
6. **余量都在噪声以内。** #5 只高 0.0007，#9/#10 只高 0.005/0.009，#6 差 0.067，#7 只差 0.0027；S1 只有 5 个被试（3033 条）。按被试 bootstrap，这些边界都会跨过阈值，因此“可行”应读作“点估计上擦线可行”，不是稳健结论；要把它变成稳健结论，需要更多未注册者被试或跨批次校准。

## 7. 合规与边界

- 标准化、PCA、原型、阈值、融合权重全部来自 Train；`loso_strict` 的每一折都真正排除了留出身份的 fit 块（不只是原型）。
- Test 只评分：先算分再读 Session；Session 从未进入特征、模型、阈值或权重。Session 也从未置 0。
- 权重选择：§2.2 的每个融合都只按 `loso_strict` 选；§2.3/§2.4 的 Pareto 与可行点是审计，不是部署选择器。最佳折中点因此标注为“审计可选、Train-only 不可选”。
- 单工作点：§4 的 11 项全部来自 `E183 0.4 + E65 0.3 + subwin6 0.3`、a=0.90、τ（paired）一个点，没有跨点拼接。
- E183 的 `loso_std` 读数用 E194 的“反事实重训 head”缓存；E183 的协议本来就排除留出身份，所以 std 与 strict 只差 0.0066。
- E192 的 WCCN 门控按 E192 代码逐行重实现（shrinkage 0.05、eigenvalue floor 1e-6、distance ratio），与 `cache/gate_arrays.npz` 的 known/unknown 相关 1.0。
