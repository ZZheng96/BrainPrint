## 2. 分支 A：对抗训练闭集骨干

结构：Conv1d(18->32,k9,s2)-BN-ELU -> (32->64) -> (64->128) -> (128->128) -> global avg pool -> Linear(128,20)，参数量 248084；输入逐 trial 去均值 + 全局 RMS 归一化。
训练：5 折各 30 epoch + 全量模型 40 epoch（早停 best epoch 22）；每 batch 都做对抗训练（PGD-3，L∞ ε=0.02×RMS），损失 0.5·CE(clean)+0.5·CE(adv)；单 epoch 平均 2.0690 s。
增强：时间平移 ±50、通道 dropout 0.1、幅值 ×[0.9, 1.1]、高斯噪声 SNR [20, 30] dB。

## 6. 回答：双分支是否让通过项数增加？

E179 的结论是「历史上没有任何单一方案能同时覆盖对抗鲁棒与跨会话开放集两侧」；在项目 18 通道上最接近的是 E170/E178，通过 3 项（#2/#3/#4）。本实验的双分支系统通过 **4 项**（#2、#3、#4、#8），相对 E170/E178 **增加 1 项**。
新增通过的项：#8。

**这个「+1」要怎么读**：新增的 #8 不是靠识别完美拿到的，而是靠门控拒识（ASafeR 把判 0 计为安全）。同一批攻击下 #7 仍差 0.0339，说明身份头虽然抗住了扰动（闭集准确率在 ε=0.02 仍有 0.978），但门控在 a=0.90 上会拒掉约 6% 的干净样本，直接把 RA 的天花板压到 0.94 以下。也就是说 #7 的瓶颈已经从「表征不鲁棒」变成了「工作点选择」，这是与 E179 时期（RA 0.4417，表征级失败）不同性质的失败。

**相对 E170/E178 的逐项变化**：#1 0.9730→0.9988、#2/#4 0.9592→0.9881、#3 0.9590→0.9878、#5 0.9094→0.9401、#6 0.4882→0.5847、#7 0.4417→0.9161、#8 0.6965→0.9840、#9 0.7210→0.6335（变差）、#10 0.6775→0.7359（变好）。所有项都在同向改善，只有 #9 变差：更严的门控提高了 S1 拒识，代价是 S2 接受下降，这正是 E179 指出的「S1+S2 由同一条 ROC 决定、只能此消彼长」。

未通过项与差距：#1 0.9988（差 0.0012）；#5 0.9401（差 0.0399）；#6 0.5847（差 0.3653）；#7 0.9161（差 0.0339）；#9 0.6335（差 0.1165）；#10 0.7359（差 0.0141）。

### 7.1 实现修正记录（全部发生在 Test 之前）

`run.log` 保留了中间过程，便于核对：

1. 门控阈值最初把「接受率 a=0.90」误读成「分数的 0.90 分位」，实际等价于 10% 接受率（Train 窗口块接受率只有 0.131）。改为仓库既有口径 `quantile(ref, 1-a)` 后，OOF 接受率回到 0.90。
2. 攻击步长方向最初写成了沿 loss 梯度上升，等于在**最小化**攻击目标（出现 RA 0.0000 这种“攻击越打越安全”的反常结果）。改为沿 loss 梯度下降后恢复正常。
3. 攻击目标最初把身份 margin 与门控 z 分数加权混合，结果梯度被门控项主导、身份攻击几乎无效。改为 A/B/C/D 四条互不混合的目标后，才分别测到两条分支的真实脆弱面。

三项都只涉及 Train 侧实现，Test 仅在全部冻结完成后评分一次。
