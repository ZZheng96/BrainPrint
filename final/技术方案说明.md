# team_hymn 决赛方案技术说明

本文档说明 `final/team_hymn` 提交包的技术原理与实现细节，对应代码为 `final/team_hymn/model.py` 与 `final/team_hymn/weights.pt`。

方案名称：`subwin6_pca96_k1 @ a=0.90`（E200 冻结方案）。
一句话概括：**把单条 4 秒 18 通道 EEG 切成 6 个子窗，在每个子窗的 5 个频带上构造通道间协方差矩阵，映射到对数欧氏空间得到 855 维几何特征；按任务标准化并降到 96 维后，与身份原型做最近邻匹配，用单一距离阈值 τ 做开集拒识。全程不需要神经网络，也不需要推理期训练。**

---

## 1. 任务与提交契约

### 1.1 决赛流程

官方流程分两阶段：

1. 注册阶段：给出被测对象 A、B、C 的带标签样本，调用 `enroll`；
2. 盲测阶段：给出 A、B、C、D、E 的样本，调用 `predict_batch`，由主办方取分数矩阵 `argmax` 得到最终标签。

对应本方案的内存状态流转：

```text
load_model(model_dir, device)      -> artifact（只读的拟合态）
enroll(artifact, x_enroll, meta, labels) -> artifact（新增 3 个原型，其余参数不变）
predict_batch(artifact, x, meta)   -> numpy (N, 24) 分数矩阵
主办方 argmax(axis=1)              -> 标签 0（未注册）/ 1-20（原有）/ 21-23（新注册）
```

## 2. 端到端数据流

```text
x (N, 18, 1200)
  │  nan/inf 置 0，转 float32，搬到 artifact 所在 device
  ▼
6 个子窗，每个 200 点（0.667 s）
  │  每个子窗独立执行下面整条链
  ▼
rFFT → 5 个理想带通掩码 → irFFT 回到时域          (N, 5, 18, 200)
  │  去均值 → 逐通道标准化（ddof=1）
  ▼
协方差/相关矩阵                                     (N, 5, 18, 18)
  │  0.05 收缩 → eigh → 特征值下限 → log 矩阵
  ▼
取上三角 171 维，非对角 ×√2                        (N, 5, 171)
  │  每频带：对角 18 维去均值；整带 z-score
  ▼
拼接为 855 维                                      (N, 855)
  │  6 个子窗取算术平均
  ▼
任务级 z-score（4×855 均值/标准差）→ PCA-96        (N, 96)
  │  与 (4, 20+3, 96) 原型做欧氏距离
  ▼
分数矩阵 (N, 24)：列 0 = -τ，列 c = -d_c
```

## 3. 技术原理

### 3.1 为什么用协方差几何而不是时域波形

EEG 的个体差异主要体现在**频段功率的空间分布**和**通道间的同步结构**上，而不在具体波形。对每个频带，先按通道标准化，再计算 18×18 相关矩阵，等价于描述"该频带下各通道之间如何协同振荡"。这个矩阵属于对称正定（SPD）矩阵锥，具有两个适合身份识别的性质：

- 对通道幅值增益不敏感（逐通道标准化后，整体增益被消掉）；
- 对时间平移和相位不敏感（相关矩阵只用二阶统计量）。

因此同一被试在不同试次上的协方差结构比原始波形稳定得多，而不同被试之间差异明显。

### 3.2 频带分解

5 个频带为 1–8 / 8–13 / 13–20 / 20–30 / 30–40 Hz，分别覆盖 δ/θ、α、β 低段、β 高段与 γ 低段。分解方式是 FFT 理想矩形掩码：

```text
spectrum = rfft(x)
mask_i   = (freq >= low_i) & (freq <  high_i)      # 第 5 个带上界取闭区间 freq <= 40
filtered = irfft(spectrum * mask_i, n=length)
```

相邻频带在边界处一个开一个闭，既不重叠也不留空隙。由于 200 点窗在 300 Hz 下的频率分辨率为 1.5 Hz，各频带实际包含的频点数不同：

| 频带 | 频率范围 | 频点数 |
|---|---|---:|
| 1 | 1–8 Hz | 5（1.5–7.5 Hz） |
| 2 | 8–13 Hz | 3（9.0–12.0 Hz） |
| 3 | 13–20 Hz | 5（13.5–19.5 Hz） |
| 4 | 20–30 Hz | 6（21.0–28.5 Hz） |
| 5 | 30–40 Hz | 7（30.0–39.0 Hz） |

矩形掩码等价于频域硬切，带内无相位失真；切完再做时域去均值，避免直流泄漏影响。

### 3.3 子窗口集成

整段 4 秒并非平稳：漂移、眨眼、注意力波动会污染全窗协方差。方案把 1200 点切成 6 个互不重叠的 200 点窗，**每个子窗独立跑完整条特征链**，最后对 6 个 855 维向量取算术平均。

注意这里不是"先平均再算协方差"：由于 `log`、逐带 z-score 都是非线性操作，子窗平均与全窗特征不等价。子窗平均相当于对局部协方差做几何量的平均，既保留短时结构，又降低单窗噪声。

### 3.4 相关矩阵、收缩与 logSPD

记第 i 个频带的标准化信号为 `Z ∈ R^{18×200}`，则

```text
C = Z Zᵀ / (L - 1)                 # L = 200，ddof = 1
C_shrunk = (1 - α) C + α · (tr(C)/18) · I,   α = 0.05
```

收缩把样本协方差朝各向同性拉近，保证特征值严格为正（200 个时间点对 18 维是充足的，但收缩能进一步稳定小特征值）。随后做矩阵对数：

```text
C_shrunk = V Λ Vᵀ,  λ_k ← max(λ_k, 1e-12)
logSPD   = V diag(log λ) Vᵀ
```

`log` 把 SPD 流形映射到其切空间（以单位阵为原点）。在切空间里，矩阵的欧氏距离近似原流形上的测地距离，于是"两个协方差矩阵有多像"可以退化为普通向量距离，后续 PCA 与原型均值都成为合法的线性操作。

### 3.5 上三角向量化与 √2 加权

对称矩阵只有 171 个独立元素（18×19/2）。取上三角并按

```text
v_ij = logSPD_ij           (i = j)
v_ij = √2 · logSPD_ij      (i ≠ j)
```

展开后，向量欧氏范数严格等于矩阵的 Frobenius 范数，非对角元素不会因只出现一次而被系统性低估。

### 3.6 频带内去趋势与 z-score

不同频带的绝对功率差异可达数量级，直接拼接会让高功率频带主导距离。处理分两步：

1. **对角去均值**：每个频带的 18 个对角元素（各通道对数功率）减去本带均值，只保留通道间的相对功率分布；
2. **整带 z-score**：对该频带 171 维减去均值、除以标准差（`unbiased=False`，下限 1e-6）。

这一步同时带来幅值不变性：整体增益、电极阻抗差异导致的统一缩放会被标准化吸收，这是方案能跨设备工作的主要原因之一。

最终每条样本得到 `5 × 171 = 855` 维特征。

### 3.7 任务条件标准化与 PCA-96

四个任务（EC / EO / Imagery / SSVEP）的协方差分布差异很大，混在一起做降维会浪费主成分。因此对每个任务 t 单独做

```text
z = (f - μ_t) / σ_t
y = (z - m_pca) · W_pca        # W_pca: (855, 96)
```

其中 `μ_t, σ_t` 是该任务全部 Train 行的均值/标准差，`m_pca, W_pca` 是 855→96 的 PCA（只用拟合行）。

PCA-96 的作用有三点：去掉 855 维中大量相关的噪声方向；把样本量/维度比拉回可控范围（拟合行 6,695 条）；让"原型均值 + 欧氏距离"在高维小样本下更稳定。96 维是在验证过的流配置中固定的，不在决赛阶段调整。

### 3.8 身份原型与最近邻

对每个 (任务 t, 身份 c) 组合，取该身份拟合行投影后的均值作为唯一原型：

```text
p_{t,c} = mean{ y_i : task_i = t, subject_i = c, i ∈ fit_rows }
```

即 k=1 的 k-means 中心。判决时只比较距离，不训练分类器，因此不存在过拟合分类边界的问题；新增用户也只是往原型表里写一行。

### 3.9 开集拒识：单一阈值 τ

最近距离 `d* = min_c ||y - p_{t,c}||₂`。若 `d* > τ` 判为未注册，否则判为最近原型对应的身份。

τ 的确定方式：在 Train 上做 5 块连续 frac 的 out-of-fold 距离（每块的原型只用其余块重建），取全部 OOF 最近距离的 90% 分位：

```text
τ = quantile(OOF nearest distances, 0.90) = 19.26382579803467
```

含义是"Train 内部已知用户接受率约 90%"。**阈值完全来自 Train，没有使用任何 Test 数据或 Test 标签**；全系统只有这一个 τ，不按任务、会话或身份分支。

### 3.10 分数矩阵为什么能用 argmax 表达判决

设第 c 列分数为 `s_c = -d_c`（c=1..20），第 0 列为 `s_0 = -τ`。则

```text
argmax(s) = 0        ⇔  -τ ≥ -d_c 对所有 c  ⇔  d* ≥ τ   （判未注册）
argmax(s) = c*       ⇔  d_{c*} < τ 且最小     （判身份 c*）
```

因此主办方的 `argmax` 与本方案的"距离 ≤ τ 则接受"完全等价，无需额外后处理。未注册身份列填 `-inf`，保证注册前不会被误选；`-inf` 不是 NaN，不违反输出有限性检查（每行第 0 列始终有限）。

## 4. 拟合流程（只用 Train）

| 阶段 | 数据 | 说明 |
|---|---|---|
| 任务统计量 `μ_t, σ_t` | 该任务全部 Train 行 | 11,304 条中的任务子集 |
| PCA 均值/基 | `frac ≤ 0.6` 的拟合行 | 每个 subject×task 内按时间顺序取前 60% |

- 原始信号除本方案内部的 FFT 带通外不做其他预处理；通道顺序与官方一致，不重排、不插值。

## 5. 新用户注册原理与实现

官方给每名新用户约 20 条带标签样本。注册流程：

```text
1. 一次性提取注册样本的 855 维特征；
2. 对每个任务 t，用该任务的 (μ_t, σ_t) 与 PCA 将该用户所有样本投影到 96 维；
3. 取均值作为该用户在每个任务下的原型；
4. 写入索引 20/21/22（即标签 21/22/23），valid 置 True。
```

数学形式：

```text
p_{t,new} = mean_i P_t(f_i),   i 遍历该新用户全部 20 条注册样本，t 遍历 4 个任务
```

三个设计点：

1. **只写原型，不动其他参数**：`μ_t`、`σ_t`、`W_pca`、τ、20 个原型的预训练值全部保持不变，符合"注册不更新预训练权重"的要求。
2. **跨任务合并样本**：由于每个任务的投影都是仿射变换，把 20 条样本同时投影到每个任务空间再取均值是合法的。Train 模拟显示，合并后每任务有约 20 个样本，比"按任务各建一个原型（每任务约 5 条）"的新用户识别率更高（0.803 对 0.694）。
3. **注册是幂等的**：同一标签重复注册会覆盖为同一均值；标签不在 21–23 的样本被忽略，不会污染 1–20 的原型。

## 6. 实现细节

### 6.1 `load_model(model_dir, device="cpu")`

- 只读 `model_dir/weights.pt`，使用 `torch.load(..., map_location="cpu", weights_only=True)`，因此权重文件必须只含张量和普通 Python 类型（本包满足）。
- 请求 `cuda*` 但 `torch.cuda.is_available()` 为假时自动退回 CPU，不会抛异常。
- 内部构建 `(4, 23, 96)` 原型表与 `(4, 23)` 布尔 valid 表：前 20 个有效，21–23 待注册。
- 返回普通 dict，包含 `device / feature / task_mu / task_sd / pca_mean / pca_basis / prototypes / valid / tau`。

### 6.2 特征提取 `_features` / `_subwindow_feature`

| 步骤 | 实现 |
|---|---|
| 输入规整 | `torch.Tensor` 先 `detach().cpu().numpy()`；统一转 `float32` 并**复制**，不触碰调用方数组 |
| 缺失值 | `np.nan_to_num(nan=0, posinf=0, neginf=0)` |
| 设备 | 整个特征链在 `artifact["device"]` 上执行，GPU 时只做一次 H2D 拷贝 |
| 子窗 | `x[..., w*200:(w+1)*200]`，w = 0..5；尾部多余采样点被忽略 |
| 频带掩码 | 预先按 `rfftfreq(200, 1/300)` 构造，逐带 `rfft → 乘掩码 → irfft(n=200)` |
| 标准化 | `std(unbiased=True)`（ddof=1），下限 1e-12 |
| 相关矩阵 | `Z Zᵀ / 199`，`trace` 用对角线求和 |
| 收缩 | `0.95·C + 0.05·(tr(C)/18)·I` |
| 矩阵对数 | `torch.linalg.eigh`，特征值 `clamp_min(1e-12)` 后取 log，`V diag(log λ) Vᵀ` |
| 向量化 | `torch.triu_indices(18, 18)`，非对角乘 `1.4142135623730951` |
| 频带内处理 | 对角 18 维减本带均值；171 维整体 z-score（`unbiased=False`，下限 1e-6） |
| 子窗聚合 | 6 个 855 维向量沿子窗维取均值 |
| 兜底 | 特征再做一次 `nan_to_num`，防止极端输入产生非有限值 |

一个子窗内的张量规模：`filtered (N, 5, 18, 200)`、`corr (N, 5, 18, 18)`、`vec (N, 5, 171)`。N=128 时峰值约 9 MB，显存/内存压力都可忽略。

### 6.3 任务解析 `_task_indices`

- 支持键：`task`、`Task`、`TASK`、`paradigm`、`Paradigm`、`task_name`、`task_folder`。
- 值先转小写并只保留字母数字，再查别名表。可直接识别：`EC/EO/Imagery/SSVEP`、`Task1`–`Task4`、`1`–`4`、`eyesclosed/eyesopen/restec/resteo/MI/VI` 等。
- 也支持中英文子串：`想象`、`闭眼`、`睁眼`、`ssvep`、`imagery` 等。
- 单条 dict 且 N>1 时广播到整批；列表长度与 N 不符时整批视为未知任务（不报错）。
- 未知任务（返回 −1）时，该行会同时用四种任务的标准化各算一次距离，取最小值。这是失败安全的降级路径，代价是"四选一取最小"会略微拉低距离、提高接受率，因此**官方若提供任务字段，应按 `EC/EO/Imagery/SSVEP` 或 `Task1`–`Task4` 传入**。
- 形如 `Task1_EC` 的复合字符串不会被解析成具体任务，会走上面的未知任务路径；不影响输出合法性。
- 完全不从文件名、目录名、样本顺序或 Session 字段推断任何信息。

### 6.4 `predict_batch`

```text
feat   = _features(artifact, x)                 # (N, 855)
tasks  = _task_indices(meta, N)                 # (N,)，-1 表示未知
dist   = full((N, 23), +inf)
for t in 0..3:
    take = (tasks == t) | (tasks < 0)           # 明确任务只走本任务；未知任务走全部
    d    = cdist(project(feat[take], t), prototypes[t])
    d    = masked_fill(~valid[t], +inf)
    dist[take] = minimum(dist[take], d)
scores[:, 0]  = -tau
scores[:, 1:] = -dist
```

- 整个函数 `@torch.no_grad()`，不训练、不读盘、不写盘、不联网、不启子进程。
- 返回值先转 CPU numpy；随后把残留 NaN 统一改为 `-inf`，并再次强制第 0 列为 `-τ`，确保"每行至少一个有限值"。
- 注册前 21–23 列为 `-inf`，`argmax` 不可能选中它们。

### 6.5 `enroll`

- 标签可为 numpy 数组或 torch Tensor，统一转 CPU `int64`。
- 只处理 21、22、23；其他标签一律跳过。
- 特征只提取一次，四种任务各做一次投影与均值，写入 `prototypes[t, uid-1]` 并置 `valid[t, uid-1] = True`。
- 原地修改并返回同一个 artifact，不复制大张量。

### 6.6 复杂度与实测性能

| 项 | 数值 |
|---|---|
| 单条特征计算 | 6 子窗 × 5 频带 × 1 次 18×18 `eigh` |
| N=128 单批（CPU） | 0.153 s / 批（实测 5 次均值） |
| N=128 单批（CUDA，RTX 3080 Laptop） | 0.035 s / 批 |
| 模型体积 | 384 KB（PCA 基 328,320 B + 原型 30,720 B + 统计量） |
| 额外依赖 | 无（仅 `os`、`numpy`、`torch`） |

### 6.7 数值与确定性

- 全链路 float32；同一设备、同一输入重复调用结果逐位一致。
- CPU 与 CUDA 的归约顺序不同，理论上末位可能不同；实测包内自测的判决结果一致（未承诺逐位相同）。
- 特征端做了两层数值保护（`split` 前 clamp 标准差、特征值 floor、最终 `nan_to_num`），全零输入和含 NaN 输入都能得到有限输出。

## 7. 合规边界

| 要求 | 本方案 |
|---|---|
| 不读测试标签 | 推理路径不读任何标签文件 |
| 不用文件名/路径/顺序推断身份 | `predict_batch` 只使用 `x` 与 `meta` |
| 不用 Session 元数据 | 代码中没有 session 分支 |
| 推理期不训练 | `predict_batch`、`enroll` 均无梯度、无优化器 |

## 9. 局限与失效模式

1. **跨时段漂移**：τ 与原型都来自单一 session。跨时段时距离分布整体上移，已注册用户会被更多拒识；初赛跨会话 clean 准确率约 0.71 即为此现象。
2. **跨设备**：训练只有单一设备。逐通道标准化和逐带 z-score 能吸收整体增益差异，但无法校正频响形状与电极位置的改变；剧烈换设备时距离会整体增大，输出偏向 −1。
3. **单阈值权衡**：τ 固定后，拒识率与接受率此消彼长，无法同时最优。当前工作点取"Train 已知接受率 90%"，初赛上表现为 S1 拒识 0.7135、S2 接受 0.7069。
4. **新用户样本少**：每名新用户约 20 条，原型噪声大；最差一次新用户识别率 0.625。
5. **任务元数据依赖**：缺少 `meta['task']` 时退化为四任务取最小距离，距离被系统性压低，接受率上升；对拒识要求高的场景会有损失。
6. **无拒识置信度**：分数矩阵只提供负距离，未做后验校准，无法表达"第二候选也很接近"这类不确定性。
