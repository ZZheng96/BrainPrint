# team_hymn 决赛方案技术说明

本文档说明 `final/team_hymn` 提交包的技术原理与实现细节。决赛规则以 `决赛说明.docx`（《技术说明与决赛评测规则》）为唯一依据，下文引用其章节号时写作“规则 x.x”。

- 代码：`final/team_hymn/model.py`
- 权重：`final/team_hymn/weights.pt`
- 方案：`subwin6_pca96_k1 @ a=0.90`（E200 冻结方案）

方案概括：把单条 4 秒 18 通道 EEG 切成 6 个子窗，在每个子窗的 5 个频带上计算通道相关矩阵，映射到对数欧氏空间得到 855 维几何特征；按任务标准化并降到 96 维后，与身份原型做最近邻匹配，用单一距离阈值 τ 判定未知用户。方案不含神经网络，推理和注册阶段都不训练。

## 2. 端到端数据流

```text
x (N, 18, 1200)
  │  nan/inf 置 0，转 float32，搬到 artifact 所在 device
  ▼
6 个子窗，每个 200 点（0.667 s）
  │  每个子窗独立执行下面整条链
  ▼
rFFT → 5 个矩形带通掩码 → irFFT 回到时域            (N, 5, 18, 200)
  │  去均值 → 逐通道标准化（ddof=1）
  ▼
相关矩阵                                             (N, 5, 18, 18)
  │  0.05 收缩 → eigh → 特征值下限 → 矩阵对数
  ▼
取上三角 171 维，非对角 ×√2                          (N, 5, 171)
  │  每频带：对角 18 维去均值；整带 z-score
  ▼
拼接为 855 维                                        (N, 855)
  │  6 个子窗取算术平均
  ▼
任务级 z-score（4×855 均值/标准差）→ PCA-96          (N, 96)
  │  与 (4, 23, 96) 原型计算欧氏距离
  ▼
分数矩阵 (N, 24)：列 0 = −τ，列 c = −d_c
```

主办方已对数据做 50 Hz 陷波、1–40 Hz 四阶 Butterworth 零相位带通、坏道球面插值、4 秒切片和逐通道去均值（规则 2.2）。本方案的 5 个频带正好覆盖 1–40 Hz，不再做额外滤波或重参考。

## 3. 技术原理

### 3.1 为什么用协方差几何

EEG 的个体差异主要体现在各频段功率的空间分布和通道间的同步结构上，单条波形本身随时间变化很大。对每个频带先逐通道标准化，再计算 18×18 相关矩阵，描述的是“该频带下各通道如何协同振荡”。这个矩阵是对称正定（SPD）矩阵，有两个适合身份识别的性质：

- 对单个通道的幅值增益不敏感（逐通道标准化消掉了增益）；
- 对时间平移和相位不敏感（只用二阶统计量）。

因此同一被试不同试次之间的相关结构比原始波形稳定，不同被试之间差异明显。

### 3.2 频带分解

5 个频带为 1–8 / 8–13 / 13–20 / 20–30 / 30–40 Hz。分解方式是 FFT 矩形掩码：

```text
spectrum = rfft(x)
mask_i   = (freq >= low_i) & (freq < high_i)      # 第 5 个带上界取 freq <= 40
filtered = irfft(spectrum * mask_i, n=length)
```

相邻频带边界一开一闭，不重叠也不留空。200 点窗在 300 Hz 下的频率分辨率为 1.5 Hz，各频带实际包含的频点数如下：

| 频带 | 频率范围 | 频点数 |
|---|---|---:|
| 1 | 1–8 Hz | 5（1.5–7.5 Hz） |
| 2 | 8–13 Hz | 3（9.0–12.0 Hz） |
| 3 | 13–20 Hz | 5（13.5–19.5 Hz） |
| 4 | 20–30 Hz | 6（21.0–28.5 Hz） |
| 5 | 30–40 Hz | 7（30.0–39.0 Hz） |

切完后在时域再去一次均值，避免直流残留。

### 3.3 子窗集成

4 秒片段并不平稳，漂移、眨眼、注意力波动会污染全窗协方差。方案把 1200 点切成 6 个互不重叠的 200 点子窗，每个子窗独立跑完整条特征链，最后对 6 个 855 维向量取算术平均。

矩阵对数和逐带 z-score 都是非线性操作，所以子窗特征的平均不等于全窗特征。它相当于在切空间里平均局部协方差，保留短时结构，同时降低单窗噪声。

### 3.4 相关矩阵、收缩与 logSPD

记某频带的标准化信号为 `Z ∈ R^{18×200}`：

```text
C        = Z Zᵀ / (L − 1)                          # L = 200，ddof = 1
C_shrunk = (1 − α) C + α · (tr(C)/18) · I,  α = 0.05
```

收缩把样本协方差向各向同性方向拉近，稳定小特征值。随后做矩阵对数：

```text
C_shrunk = V Λ Vᵀ,  λ_k ← max(λ_k, 1e-12)
logSPD   = V diag(log λ) Vᵀ
```

矩阵对数把 SPD 流形映射到单位阵处的切空间。在切空间里，矩阵的欧氏距离近似流形上的距离，于是后续的 PCA 和原型均值都可以按普通向量处理。

### 3.5 上三角向量化与 √2 加权

18×18 对称矩阵有 171 个独立元素。取上三角时对角元素保持不变，非对角元素乘 √2。这样向量的欧氏范数等于矩阵的 Frobenius 范数，非对角元素不会因为只取一次而被低估。

### 3.6 频带内去趋势与 z-score

不同频带的绝对功率可相差数量级，直接拼接会让高功率频带主导距离。处理分两步：

1. 对角去均值：每个频带的 18 个对角元素（各通道对数方差）减去本带均值，只保留通道间的相对分布；
2. 整带 z-score：该频带 171 维减均值、除标准差（`unbiased=False`，下限 1e-6）。

这一步也让特征对整体幅值缩放不敏感。跨设备场景下，如果新设备只是整体增益不同，这部分差异会被吸收；频响形状或电极位置不同则无法校正（见第 8 节）。

最终每条样本得到 `5 × 171 = 855` 维特征。

### 3.7 任务条件标准化与 PCA-96

训练数据包含四种任务：闭眼静息（EC）、睁眼静息（EO）、视觉想象（Imagery）、SSVEP（规则 2.1）。四种任务的协方差分布差异很大，因此对每个任务 t 分别标准化后再投影：

```text
z = (f − μ_t) / σ_t
y = (z − m_pca) · W_pca        # W_pca: (855, 96)
```

`μ_t, σ_t` 用该任务全部 Train 行计算；`m_pca, W_pca` 只用拟合行（frac ≤ 0.6，共 6,695 条）计算，四种任务共用一个 PCA。PCA-96 去掉大量相关的噪声方向，使“原型均值 + 欧氏距离”在样本量有限时更稳定。96 维在研发阶段确定，决赛不调整。

### 3.8 身份原型与最近邻

对每个（任务 t，身份 c）取拟合行投影的均值作为唯一原型：

```text
p_{t,c} = mean{ y_i : task_i = t, subject_i = c, i ∈ fit_rows }
```

判决只比较距离，没有可训练的分类边界。新增用户只需要往原型表里写入一行，这正是规则 3.4 允许的“计算和保存新的身份模板、类别原型”。

### 3.9 未知用户拒识：单一阈值 τ

最近距离 `d* = min_c ||y − p_{t,c}||₂`。若 `d* > τ`，判为未注册（最终标签 −1）；否则判为最近原型的身份。

τ 的确定方式：Train 上做 5 块连续 frac 的 out-of-fold 距离（每块的原型只用其余块重建），取全部 OOF 最近距离的 90% 分位：

```text
τ = quantile(OOF nearest distances, 0.90) = 19.26382579803467
```

含义是 Train 内已知用户约 90% 被接受。τ 只来自 Train，没有使用任何测试数据或测试标签（规则八：不得用测试真实标签做阈值优化）。全系统只有这一个 τ，不按任务、时段、设备或身份分支。

### 3.10 分数矩阵与 argmax 的等价性

设第 c 列分数 `s_c = −d_c`（c = 1..23，未注册的 c 为 −inf），第 0 列 `s_0 = −τ`：

```text
argmax(s) = 0    ⇔  −τ ≥ −d_c 对所有 c  ⇔  d* ≥ τ   → 主办方映射为 −1
argmax(s) = c*   ⇔  d_{c*} < τ 且最小              → 身份 c*
```

主办方只取 argmax（规则 6.2），这与“距离不超过 τ 才接受”的判决一致，无需后处理。21–23 列在注册前为 −inf，不会被选中；第 0 列始终有限，满足“每行至少一个有限值”。

## 4. 拟合流程（只用 Train）

| 参数 | 拟合数据 | 说明 |
|---|---|---|
| 任务统计量 `μ_t, σ_t` | 该任务全部 Train 行 | 4 × 855 |

## 5. 新用户注册（规则 3.4、6.2(3)）

主办方为每名新用户提供 20 条带标签注册样本，共 60 条，标签为 21、22、23。注册流程：

```text
1. 对 60 条注册样本一次性提取 855 维特征；
2. 对每个任务 t，用该任务的 (μ_t, σ_t) 和 PCA 把某个新用户的全部样本投影到 96 维；
3. 取均值作为该用户在任务 t 下的原型；
4. 写入原型表索引 20/21/22（即标签 21/22/23），并置有效位。
```

数学形式：

```text
p_{t,new} = mean_i P_t(f_i)，i 遍历该用户全部 20 条注册样本，t 遍历 4 个任务
```

设计要点：

1. **不更新预训练权重**：`μ_t`、`σ_t`、PCA、τ 和 1–20 号原型都保持不变，只新增模板，符合规则 6.2 和 6.6。
2. **跨任务合并样本**：每个任务的投影都是仿射变换，所以可以把 20 条样本投影到每个任务空间后取均值。规则没有承诺注册样本在四种任务间的分布，按任务分开建原型时每个任务可能只有约 5 条。Train 模拟中，合并方式的新用户识别率为 0.803，按任务分开为 0.694。
3. **只用注册样本**：注册时不接触任何测试数据（规则 6.2：不得使用测试数据或测试标签）。
4. **输入容错**：标签不在 21–23 的样本被跳过，不会改动 1–20 号原型；同一标签重复注册会覆盖为同一均值。

## 6. 实现细节

### 6.1 `load_model(model_dir, device="cpu")`

- 只读 `model_dir/weights.pt`，使用 `torch.load(..., map_location="cpu", weights_only=True)`，不读 `model_dir` 之外的任何路径。
- 请求 `cuda*` 但 `torch.cuda.is_available()` 为假时退回 CPU，不抛异常（规则 6.2：不得假设一定在 GPU 上）。
- 构建 `(4, 23, 96)` 原型表和 `(4, 23)` 有效位表：前 20 个有效，21–23 待注册。
- 返回普通 dict：`device / feature / task_mu / task_sd / pca_mean / pca_basis / prototypes / valid / tau`。

### 6.2 特征提取 `_features` / `_subwindow_feature`

| 步骤 | 实现 |
|---|---|
| 输入规整 | `torch.Tensor` 先 `detach().cpu().numpy()`；统一转 float32 并复制，不修改调用方数组 |
| 非有限值 | `np.nan_to_num(nan=0, posinf=0, neginf=0)` |
| 设备 | 整条特征链在 `artifact["device"]` 上执行，GPU 时只做一次主机到显存的拷贝 |
| 子窗 | `x[..., w*200:(w+1)*200]`，w = 0..5 |
| 频带掩码 | 按 `rfftfreq(200, 1/300)` 构造，`rfft → 乘掩码 → irfft(n=200)` |
| 标准化 | `std(unbiased=True)`，下限 1e-12 |
| 相关矩阵 | `Z Zᵀ / 199` |
| 收缩 | `0.95·C + 0.05·(tr(C)/18)·I` |
| 矩阵对数 | `torch.linalg.eigh`，特征值 `clamp_min(1e-12)` 后取 log |
| 向量化 | `torch.triu_indices(18, 18)`，非对角乘 `1.4142135623730951` |
| 频带内处理 | 对角 18 维减本带均值；171 维整体 z-score（`unbiased=False`，下限 1e-6） |
| 子窗聚合 | 6 个 855 维向量取均值 |
| 兜底 | 特征再做一次 `nan_to_num` |

N=128 时单个子窗的中间张量为 `(128, 5, 18, 200)`，峰值约 9 MB。

### 6.3 任务字段解析 `_task_indices`

- 读取键：`task`、`Task`、`TASK`、`paradigm`、`Paradigm`、`task_name`、`task_folder`。
- 值转小写并只保留字母数字后查别名表，可识别 `EC/EO/Imagery/SSVEP`、`Task1`–`Task4`、`1`–`4`、`eyesclosed/eyesopen/MI/VI` 等，也识别 `想象`、`闭眼`、`睁眼` 等中文子串。
- 单个 dict 且 N>1 时广播到整批；列表长度与 N 不符时整批视为未知任务。
- 任务未知时，该行在四种任务的标准化下各算一次距离，取最小值。这条降级路径保证输出合法，代价是距离被系统性压低、接受率上升。
- 任务字段只用于选择该任务的标准化统计量，不用于推断身份。规则 6.6 禁止“从文件名、目录名、元数据反推身份”，本方案不读文件名、目录名、样本顺序和 session 字段。
- 规则未规定决赛 `meta` 的具体键名。若主办方不提供任务字段，方案自动走四任务取最小的路径。

### 6.4 `predict_batch`

```text
feat   = _features(artifact, x)                 # (N, 855)
tasks  = _task_indices(meta, N)                 # (N,)，−1 表示未知
dist   = full((N, 23), +inf)
for t in 0..3:
    take = (tasks == t) | (tasks < 0)           # 已知任务只走本任务；未知任务走全部
    d    = cdist(project(feat[take], t), prototypes[t])
    d    = masked_fill(~valid[t], +inf)
    dist[take] = minimum(dist[take], d)
scores[:, 0]  = −tau
scores[:, 1:] = −dist
```

- 整个函数在 `@torch.no_grad()` 下运行，不训练、不读写磁盘、不联网、不启子进程。
- 结果转为 CPU numpy；残留 NaN 改为 −inf，并再次把第 0 列设为 −τ。

### 6.5 `enroll`

- labels 可为 numpy 数组或 torch Tensor，统一转 CPU int64。
- 只处理 21、22、23，其余标签跳过。
- 特征只提取一次，四种任务各做一次投影与均值，写入 `prototypes[t, uid−1]` 并置 `valid[t, uid−1] = True`。
- 原地更新并返回同一个 artifact。

### 6.6 复杂度与实测耗时

| 项 | 数值 |
|---|---|
| 单条计算量 | 6 子窗 × 5 频带 × 1 次 18×18 `eigh` |
| N=128 单批（CPU） | 0.153 s（5 次均值） |
| N=128 单批（CUDA，RTX 3080 Laptop） | 0.035 s |
| 权重体积 | 392,921 B |

规则 6.7 提到单队推理/注册时间和内存/显存限制，但未给出数值；以上耗时和占用远低于常见限制。

### 6.7 数值与确定性

- 全链路 float32；同一设备、同一输入重复调用结果逐位一致。
- CPU 与 CUDA 的归约顺序不同，末位可能不同；包内自测中两者判决一致。
- 标准差下限、特征值下限和最终 `nan_to_num` 保证全零输入和含 NaN 输入也能得到有限输出。

## 8. 各场景的预期表现与风险

决赛四个场景的官方指标目前都是 N/A：隐藏测试数据和真实标签不公开（规则八）。以下读数只来自训练数据和初赛 Test 的预测审计，用于说明方案强弱，不代表决赛成绩。

### 8.1 现有读数

| 读数 | 数值 | 口径 |
|---|---:|---|
| 决赛官方 Clean Accuracy / Unknown Rejection Rate | N/A | 无真实标签 |
| 决赛 AUC / F1 | N/A | 同上 |
| 初赛 Test session1 拒识率 | 0.7135 | 预测工程审计读数，非官方真值 |
| 初赛 Test session2 接受率 | 0.7069 | 同上；可近似看作跨时段场景的接受上限参考 |
| Train LOSO AUROC | 0.8835 | 留一身份，衡量已知/未知分离 |
| Train U@95% | 0.3292 | 已知接受率固定 95% 时的未知拒识率 |
| 身份头 OOF macro-F1 | 0.9882 | 5 块 OOF 闭集口径（本门控不使用该头） |

Train 上按决赛四场景做的模拟（20 次随机抽取，seed 20261116）：随机选 3 人作为新用户，各取 20 条早期试次注册；另选 3 人删除原型作为未注册者；其余 14 人为已注册用户；测试集为后 20% 试次。

| 对应场景 | 均值 | 最差一次 |
|---|---:|---:|
| 已注册用户识别（同时段） | 0.798 | — |
| 新用户注册后识别 | 0.803 | 0.625 |
| 未注册用户拒识 | 0.659 | 0.529 |

这些是同时段（session1）读数，且 PCA 拟合时见过所有 20 人，结果偏乐观；没有设备变化，无法反映跨设备场景。

### 8.2 分场景风险

1. **已注册用户跨时段**：原型和 τ 都来自单一时段。跨时段时距离整体增大，已注册用户更容易被拒识。初赛 session2 的接受率约 0.71，是这个场景最直接的参考。
2. **已注册用户跨设备**：训练只有一种设备。逐通道标准化和逐带 z-score 能吸收整体增益差异，无法校正频响形状、电极位置和参考方式的变化。规则 2.2 说明跨设备数据如有不同采样率、通道配置或参考方式会单独说明；`predict_batch` 的输入仍固定为 `(N, 18, 1200)`。若设备差异大，距离会整体增大，更多样本被判为 −1，这个场景的准确率是四个场景中最不确定的。
3. **新用户注册与跨时段识别**：每人只有 20 条注册样本，原型噪声大；测试数据又与注册数据不同时段，叠加了跨时段漂移。新用户原型与 1–20 号原型共存时，相近的两人可能互相混淆。
4. **未注册用户检测**：τ 固定后，未知拒识率和前三个场景的接受率此消彼长。当前工作点按 Train 已知接受率 90% 设定，没有为某个场景单独优化。由于跨时段/跨设备会让所有距离增大，未注册用户的拒识率在决赛中可能高于 Train 模拟，但已注册用户的误拒也会同步增加。
5. **任务字段缺失**：若决赛 `meta` 不含任务信息，方案退化为四任务取最小距离，距离被压低，接受率上升，未注册检测会变弱。
6. **分数未校准**：分数矩阵只给负距离，没有后验概率，无法表达“第二候选也很接近”的不确定性。主办方只取 argmax，这不影响评分。
